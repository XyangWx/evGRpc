# DisplayService Charging Reports Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add 3 TZ-aware charging report RPCs (year / month / day) to `DisplayService`, gated by a TIMESTAMPTZ schema migration so that the date grouping reflects the operator's local timezone, not UTC.

**Architecture:** Two-phase build. (1) Migrate `charging.StartTime` / `EndTime` from bare `TIMESTAMP` to `TIMESTAMPTZ` via an idempotent SQL migration — this is the precondition that makes TZ-aware SQL meaningful. (2) Add three new RPCs (`GetDailyChargingReport`, `GetMonthlyChargingReport`, `GetAnnualChargingReport`) that return a new `ChargingReport` message. Each RPC aggregates over `charging` only (no `consumption` mix-in), using `EXTRACT` / `::date` which is session-TZ-aware for `TIMESTAMPTZ` columns. Validator rejects year<1900, month out of range, day out of range, and day-vs-month invalid combos (Feb 30 etc.) as `INVALID_ARGUMENT`. No-data returns `OK` with zeros — deliberately diverging from the existing `GetMonthlyReport` INTERNAL-on-empty quirk.

**Tech Stack:** C++17, gRPC (proto3), libpqxx, PostgreSQL 14+ (TIMESTAMPTZ with `current_setting('TIMEZONE')`), GoogleTest, CMake (Ninja), `bash` for `scripts/load_schema.sh`.

```sql
-- sql/002_charging_timestamptz_migration.sql
-- Migrate charging.StartTime / EndTime from TIMESTAMP to TIMESTAMPTZ.
-- Idempotent: the DO $$ BEGIN guard checks BOTH columns and only runs
-- the ALTER if at least one is still bare TIMESTAMP. Existing TIMESTAMP
-- values are interpreted as UTC (the dev environment's convention and
-- the spec's recommended assumption for production deploys).
--
-- Run AFTER sql/001_initial.sql has been applied at least once.

BEGIN;

DO $$ BEGIN
  IF EXISTS (
    SELECT 1 FROM information_schema.columns
    WHERE table_name = 'charging'
      AND column_name IN ('StartTime', 'EndTime')
      AND data_type = 'timestamp without time zone'
  ) THEN
    ALTER TABLE charging
      ALTER COLUMN StartTime TYPE TIMESTAMPTZ USING StartTime AT TIME ZONE 'UTC',
      ALTER COLUMN EndTime   TYPE TIMESTAMPTZ USING EndTime   AT TIME ZONE 'UTC';
  END IF;
END $$;

COMMIT;
```

namespace evgrpc {
// Returns the last valid day of (year, month). Handles Gregorian leap

int LastDayOfMonth(int year, int month);
}  // namespace evgrpc

```cpp
// src/util/last_day_of_month.cc
#include "util/last_day_of_month.h"

namespace evgrpc {
int LastDayOfMonth(int year, int month) {
  static constexpr int kDays[] = {31, 28, 31, 30, 31, 30,
                                  31, 31, 30, 31, 30, 31};
  int days = kDays[month - 1];
  if (month == 2) {
    const bool leap = (year % 4 == 0 && year % 100 != 0) || (year % 400 == 0);
    if (leap) days = 29;
  }
  return days;
}
}  // namespace evgrpc
```

                          "year must be >= 1900");

    scope.set_status(s); return s;

    pqxx::params p;
    p.append(req->year()); p.append(req->month()); p.append(req->day());
    p.append(req->vehicle_id());

        "SELECT "
        "  COALESCE(SUM(c.Cost), 0)::DOUBLE PRECISION AS total_cost, "
        "  COALESCE(SUM(c.KwhCharged), 0)::DOUBLE PRECISION AS total_kwh, "
        "  COUNT(*)::INT AS count "
        "FROM charging c "
        "WHERE c.StartTime::date = make_date($1, $2, $3) "
        "  AND (length($4) = 0 OR c.VehicleId::text = $4)";
